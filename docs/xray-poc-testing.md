# Xray-core PoC: сборка и проверка на iPhone

Ветка `feature/xray-core-migration`. Ядро — Xray-core v26.11.9 через libXray v26.11.9.
Реализация на sing-box осталась в репозитории (сборка без флага `MONO_CORE_XRAY`) и целиком —
в ветке `mono-vpn-ios-mvp-53b819` (коммит `a00087f`).

> **Статус.** Код написан и проверен без устройства: Go-код libXray/Xray-core компилируется для
> `ios/arm64` с закреплённым `go.sum`, скрипт сборки проходит до шага iOS SDK, форма
> конфигурации Xray проверена `xray run -test` (v26.11.9) для трёх целевых транспортов.
> **Swift-код не компилировался, на iPhone ничего не запускалось** — это и есть цель проверки ниже.

## 1. Сборка на Mac

Требования: Xcode 16+, Go (`brew install go`), git. Точный Go 1.27.3 скачается сам.

```bash
git fetch origin && git checkout feature/xray-core-migration
```

```bash
MonoVPN/Scripts/build-libxray.sh
```

Только для iPhone (быстрее, без симулятора и unit-тестов на нём):

```bash
PLATFORMS=ios MonoVPN/Scripts/build-libxray.sh
```

Ожидаемый результат: `Frameworks/LibXray.xcframework` и `Frameworks/LIBXRAY_VERSION` с
`libXray: v26.11.9 (5a0f7d8…)`, `xray-core: v26.11.9`. Скрипт сам проверяет коммит тега,
пин Xray-core в `go.mod` и `go mod verify`.

Затем в Xcode: открыть `MonoVPN.xcodeproj`, Product → Clean Build Folder (⇧⌘K), схема `MonoVPN`,
выбрать iPhone, Run. В `Frameworks` должен быть только `LibXray.xcframework` (Libbox не нужен и не линкуется).

Unit-тесты (нужен срез симулятора, т. е. сборка без `PLATFORMS=ios`):

```bash
xcodebuild test -project MonoVPN.xcodeproj -scheme MonoVPN -destination 'platform=iOS Simulator,name=iPhone 17' -only-testing:MonoVPNTests CODE_SIGNING_ALLOWED=NO
```

Если сборка не проходит — пришлите текст ошибок из Report Navigator (⌘9).

## 2. Подготовка на iPhone

1. Удалить старую версию приложения (сброс кэша экрана загрузки и VPN-профиля не обязателен, но упрощает проверку).
2. Установить сборку, открыть приложение. Подписка, сохранённая сборкой с sing-box, **обновится сама**
   при запуске (она разобрана для другого ядра). Если нет сети — нажать «Обновить» в «Серверах».
3. Ожидаемо: из 56 серверов поддерживаются TCP, gRPC и XHTTP — `transport:xhttp` и
   `grpcAuthorityMismatch` больше не встречаются (проверить в «Подписка → Диагностика импорта»).

## 4. Диагностика

**В приложении:** «Подписка → Диагностика импорта → Packet Tunnel»: ядро и версия, время запуска
туннеля и ядра, текущая/пиковая память (phys_footprint — величина, которую iOS сравнивает с лимитом
~50 МБ), остаток до лимита (`os_proc_available_memory`), причина последней остановки
(`NEProviderStopReason`), очищенная ошибка запуска и последние события (запуск, остановка, смена
сети, нехватка памяти). Текст выделяется и копируется. Секретов, адресов серверов и URL там нет.

**Если расширение убито по памяти,** iOS не вызывает `stopTunnel`; при следующем запуске в событиях
появится «Предыдущая сессия завершилась без остановки туннеля (пик памяти N МБ)».

**Console.app** (Mac, iPhone подключён кабелем): фильтр `subsystem:com.irklch.monovpn`,
категории `PacketTunnel`, `Memory`, `SubscriptionDiagnostics`. Память пишется раз в 30 с и при росте пика.

**Память в Xcode:** Debug → Attach to Process → `PacketTunnel`, Debug Navigator → Memory.

Что прислать после проверки: заполненную таблицу, блок «Packet Tunnel» из диагностики (скопировать
текст) и, при ошибках, строки Console.app категории `PacketTunnel`.

## 5. Если что-то не работает

| Симптом | Что проверить |
|---|---|
| Ошибка «TUN file descriptor not found» | Сообщить: значит, utun не найден перебором `getsockopt` |
| Ошибка `runXray: …` | Текст ошибки (очищенный) из диагностики; уточнить транспорт сервера |
| Подключено, но сайты не открываются | dnsleaktest не открывается → DNS; открывается по IP (`https://1.1.1.1`) → DNS, иначе — соединение с сервером |
| Расширение перезапускается | Пик памяти и событие «завершилась без остановки» |

## 6. Как вернуть sing-box

Либо собрать ветку `mono-vpn-ios-mvp-53b819`, либо в этой ветке: убрать `MONO_CORE_XRAY` из
`MonoVPN/Config/Identifiers.xcconfig`, собрать `MonoVPN/Scripts/build-libbox.sh` и в target
`PacketTunnel` → General → Frameworks and Libraries заменить `LibXray.xcframework` на `Libbox.xcframework`.
